1 Getting started

Log in and find your subject

  1. Log in at the admin login page with your editor/admin account.
  2. Open the Question Builder tab. The pills across the top show every subject mapped to you — if you don't see a subject you expect, ask an admin to map it to your account.
  3. Click a pill to load that subject's units and chapters into the tree on the left.
👁 If a subject pill loads but the Save button is greyed out with a "View only" note, you have read access but not edit access to that subject — ask an admin to grant can_edit.

2 Creating a subject

Only needed once per new topic — most days you'll skip straight to step 3

  1. Click + New Subject.
  2. Pick the Subject Name from the dropdown (e.g. Accounts, Economics, Physics).
  3. Type a Subject Topic Name — this is the specific version you're authoring, e.g. "Introduction to Journal Entries". It's required.
  4. The Subject Code fills in automatically — you don't type it. It's generated from the subject name and a running number, e.g. AC0001, then AC0002, then AC0003.
  5. Pick a color (used for badges/highlights across the app) and click Create — this creates and saves the subject in one step, so it's safely in the database right away.
Picking the same Subject Name again (e.g. Accounts a second time) is completely fine — it just creates a new row with the next code (AC0002) and its own Subject Topic Name. You don't need to worry about "duplicates."

3 Units & chapters

The tree on the left — your table of contents

📎 "Unit" and "Chapter" are just the field labels in this tool — what they represent is entirely up to your subject. Use whatever structure fits your programme: a school subject might use Unit 1 → Chapter 1, a course might use Week 1 → Day 1, a certification track might use Module A → Lesson 1. The learner only ever sees your titles, never the words "Unit" or "Chapter."
  • Units are the top-level grouping a learner sees in the sidebar — name it to match your programme (e.g. "Unit 1: Fundamentals", "Week 1", "Module A: Getting Started").
  • Chapters live inside a unit — each one gets its own theory (concept) and its own set of practice questions. Name it to fit too (e.g. "Chapter 1", "Day 1: Introduction", "Lesson 1").
  • Click + Add Unit or + Add Chapter and type a title. Click any chapter row to open it in the editor on the right.
  • Use ✎ to rename, 🗑/✕ to delete. Deleting a unit deletes every chapter (and every question) inside it — there's a confirm prompt, but there's no undo after you save.
✓ Do
Pick one naming convention per subject and stick with it — mixing "Week 1" and "Unit 2" in the same subject confuses learners scanning the sidebar.
✗ Don't
Feel locked into "Unit/Chapter" wording — it's a label in this tool, not a requirement for how you structure your content.

4 Writing the concept (theory)

The explanation a learner reads before attempting questions

  1. Select a chapter, then open the 💡 Concept / Theory section.
  2. Set a Concept Title (defaults to the chapter title).
  3. Leave Enable LaTeX checked if you'll write any math — you can then use $x^2$ for inline math and $$x^2$$ for a centered equation, anywhere text is accepted.
  4. Build the body out of content blocks — click any of the + type buttons to add one. Reorder with ↑ / ↓, remove with ✕.
There's no single "concept text box" — theory is always a sequence of blocks (heading, paragraph, list, table, etc.), stacked in the order you add them. This is what lets a chapter mix prose, a table, an example, and a video in one flow.

heading / paragraph / note / formula

The four "plain text" blocks — a heading breaks up the page, a paragraph is body text, a note renders as a highlighted 💡 callout, and a formula renders in a dark, centered code-style box (good for a single key equation).

{ "type": "heading", "text": "Introduction" }
{ "type": "paragraph", "text": "A journal entry records a transaction using $Debit = Credit$." }
{ "type": "note", "text": "Every entry must balance — total debits always equal total credits." }
{ "type": "formula", "text": "Assets = Liabilities + Equity" }

list / summary

A bulleted list. summary is the same shape, styled as a "📌 Summary" box — use it for a recap at the end of a chapter.

{ "type": "list", "items": ["First point", "Second point"] }
Tip: in the editor, paste several lines from a doc directly into any list item box — it automatically splits them into separate items instead of one long line.

table

{
  "type": "table",
  "headers": ["Account", "Debit", "Credit"],
  "rows": [
    ["Cash", "5000", ""],
    ["Sales", "", "5000"]
  ]
}

In the editor, you can paste a table straight from Excel/Sheets (tab-separated) using the "📋 Paste table data" option instead of typing cell by cell.

syntax

A dark, monospace code block — use for SQL, formulas, or any code snippet.

{ "type": "syntax", "language": "sql", "code": "SELECT * FROM Student WHERE Marks > 80;" }

image / video

{ "type": "image", "title": "Ledger format", "image": "(uploaded file or URL)", "pdf": "" }
{ "type": "video", "title": "Walkthrough", "url": "https://youtube.com/watch?v=...", "start": "1:30" }

Upload an image directly with the file picker in the editor — no need to host it yourself. For video, paste any YouTube link; start is optional (seconds, or mm:ss).

steps / exercise

Both show a numbered list. steps is a plain walkthrough; exercise is styled as a boxed "✏️ Practice" callout — use it for a problem you want visually separated from the theory.

{ "type": "steps", "title": "How to post an entry", "steps": ["Identify the accounts", "Determine debit/credit", "Record the entry"] }

example

The richest block — a worked example with an optional input, numbered steps, a formula, a result, and an image, all in one card.

{
  "type": "example",
  "title": "AVERAGEIF() Example",
  "before": "Find the average marks of students in Physics.",
  "steps": ["Select the marks range", "Apply the condition"],
  "formula": "=AVERAGEIF(B2:B20,\"Physics\",D2:D20)",
  "after": "Average marks of Physics students"
}

5b Key Formulas

A highlighted recap box at the end of the concept — separate from the body blocks

Use this when a chapter has a small set of formulas worth a learner glancing back at, without hunting through the paragraph blocks. Each entry becomes its own chip in a "Key Formulas" box, rendered after all the content blocks. Add entries with + Add Key Formula under the 🧮 Key Formulas section — LaTeX works here too when it's enabled on the concept.

{
  "formulas": [
    "Dimensional formula: $[M^a L^b T^c]$",
    "Absolute error $\\Delta a = |a_{measured} - a_{true}|$",
    "Percentage error $= (\\Delta a/a) \\times 100$"
  ]
}
✓ Use it for
2–5 formulas the learner should memorize or reference repeatedly through the chapter's questions.
✗ Don't use it for
A one-off equation used in a single worked example — that belongs in a formula content block, or inside an example block instead.

5c Case Studies / shared passages

One passage, reused across a group of questions

Create a case once under 📋 Case Studies / Shared Passages — a title, a passage, and an optional image — then assign it to any question via that question's "Part of Case / Passage" dropdown in the question editor. Every question sharing a case shows the passage once, right before that group of questions, instead of repeating it per question.

Use this for comprehension-style or scenario-based questions — e.g. a paragraph describing a company's transactions, followed by 3–4 questions about it — rather than pasting the same passage into each question's own text.
Deleting a case clears the caseId on any question that referenced it (they just become standalone questions again) — it won't delete the questions themselves.

6 SQL Playground — only shown for the SQL subject

A live, runnable sandbox attached to the chapter

  1. Open the 🛢️ SQL Playground section (visible only when the subject code is SQL).
  2. Schema: the DDL + seed INSERT statements that run automatically before the learner types anything — this is what their queries will run against.
  3. Sample Queries: a few starter queries shown as clickable chips, so a learner can try something before writing their own.
{
  "schema": "CREATE TABLE Student (Roll_No INT, Name TEXT, Marks INT);\nINSERT INTO Student VALUES (1,'Riya',88);",
  "sampleQueries": ["SELECT * FROM Student;", "SELECT Name FROM Student WHERE Marks > 80;"]
}
If you leave the schema blank, the learner-facing playground falls back to a generic demo table — always fill this in for a real SQL chapter so the practice matches the concept you just taught.

7 Adding practice questions

Five question types — pick whichever fits what you're testing

TypeWhat it isAnswer shape
MCQSingle correct optionExactly one option checked
MSQMultiple correct optionsOne or more options checked
NATNumeric-answer typeA number, optionally within a tolerance, with an optional unit
ARAssertion-Reason — a statement (A) and a reason (R); learner picks how they relateOne of 4 fixed relationship options checked
MATCHMatch items in Column A to Column BA list of correct left ↔ right pairs
  1. In the Practice Questions section, click + MCQ, + MSQ, + NAT, + Assertion-Reason, or + Match the Following.
  2. For MCQ/MSQ/AR: fill in each Option and mark the correct one(s) with the radio/checkbox next to it. AR's four options come pre-filled with the standard "Both A and R are true and R explains A" wording — you just fill in the Assertion and Reason text above them and pick the correct relationship.
  3. For NAT: enter the Correct Answer, an optional Tolerance, and an optional Unit.
  4. For MATCH: rename the Column A / Column B titles if useful (e.g. "Standard" / "Covers"), then add each correct pair with + Add Pair — order doesn't matter, the learner sees them shuffled.
  5. Optionally attach a Question Image and choose whether it appears above or below the question text.
  6. If this question belongs with a shared passage, pick it from Part of Case / Passage at the top of the question editor (see §5c).
  7. Write an Explanation — see §9 for adding media to it.
Choosing a type: use MCQ for one right answer, MSQ when more than one option can be correct, NAT for a calculated number, AR to test whether a learner understands why something is true (not just whether it is), and MATCH for pairing/classification-style knowledge (standards ↔ definitions, terms ↔ meanings, causes ↔ effects).

8 Text vs. image options — the rules

How an option renders depends on what you fill in

You fill inLearner sees
Text onlyA. Option A
Image only (text left blank)A. [Image] — no empty text shown
Text + ImageA. Option A [Image] — text first, then image
✓ Do
Leave the text box empty if an option is purely a picture (e.g. a chart, a diagram). The app hides the empty text automatically.
✗ Don't
Type a placeholder like "See image" just to fill the box — it will show up as real option text next to the picture.

Attach an option image with the 🖼 icon next to that option — it uploads directly, no separate hosting needed.

9 Explanations — text, image, video, or link

Shown to the learner right after they answer

An explanation isn't limited to plain text. Under the Explanation field you can also add:

  • Explanation Image — a diagram or worked-out image.
  • Explanation Video — a YouTube URL; it embeds directly in the explanation box.
  • Explanation Link — a reference link the learner can click to read more.

Use as many of these as are useful together — e.g. a short text explanation plus a diagram is common and fully supported.

10 Importing content from a file

For writing offline in a spreadsheet-to-JSON tool or your own editor

  1. Click Download Template to get a ready-to-fill JSON file with the exact shape the builder expects.
  2. Fill it in offline — one or more units, each with chapters, concept blocks, and questions.
  3. Click Import JSON and choose your file. You'll be asked to confirm before anything is added.
  4. Review the imported units/chapters in the tree, then Save — importing only changes what's in front of you; nothing touches the database until you save.
IDs are always regenerated on import, so two people's offline files never collide when merged into the same subject.

11 Saving & permissions

  • Nothing is written to the database until you click Save (or Create when making a brand-new subject) — everything before that is a local, in-browser draft.
  • Every save is logged with your name and the time, so changes are always traceable.
  • If you navigate away with unsaved changes, the browser will warn you before leaving the page.
  • Editors can only save subjects an admin has explicitly mapped to them with edit access — admins and super admins can save any subject.

✓ Before-you-save checklist

  • Chapter title is clear and matches what's in the concept
  • Concept has at least a heading + paragraph — not left empty
  • Any math uses $...$ / $$...$$ and LaTeX is enabled
  • Images are uploaded directly, not linked to an external page that could go down
  • Every question has at least one option (or a NAT answer/AR relationship/MATCH pairs) and a correct answer marked
  • Option text boxes are left blank where an option is image-only
  • Explanation is filled in for every question — text, or text + media
  • Key Formulas box only has formulas worth repeated reference, not one-off working
  • Case Studies are assigned to the right group of questions, not left orphaned
  • SQL subjects: schema and sample queries are filled in, not left default
  • Previewed the chapter (👁 Preview) before saving
