How the Admin Panel Works

A one-page reference for everything editors and admins can do.

On this page
1. Roles & permissions 2. Question Builder 3. Multiple versions of a subject 4. JSON template & import 5. Team & editor requests 6. Data, Statistics & Feedback 7. What "Save" actually does 8. Other pages on this site
1. Roles & permissions

super_admin

Full control — manage any user including other admins, map subjects to editors, edit/save any subject, see all data.

admin

Create/edit/delete editor accounts, map subjects, edit/save any subject, review editor requests, see all data. Cannot manage other admins/super_admins.

editor

Only sees the subjects an admin has mapped to them, and can only edit ones marked "can edit". Everything (Data, Statistics, Feedback) is scoped to those subjects.

2. Question Builder

Subject → Unit → Chapter

Every subject has units, each unit has chapters. Each chapter has a Concept (theory content) and a set of Practice Questions.

Content blocks

Heading, Paragraph, List, Table, Note, Formula, Syntax/Code, Image, Video, Steps, Exercise, and Example (worked example with before/steps/formula/after) — mix and reorder freely with the ↑↓ arrows.

Questions

MCQ (one correct), MSQ (multiple correct), NAT (numeric answer with tolerance). Each question and each option can have its own image.

SQL Playground

Only shows up for the SQL subject — a schema + sample queries per chapter, which learners can run for real in the browser (no server involved, uses sql.js/WASM).

🔍 Find Chapter

Search across every subject you can see by chapter title or ID — useful once you have a lot of content.

👁 Preview

Shows exactly what a chapter will look like to a learner (Live Preview) or the raw JSON that gets saved (Raw JSON tab) — check this before saving.

3. Multiple versions of a subject

If the same subject needs more than one version — e.g. "Class 6 Physics — Prepared by Muthu" vs "...by Karthi" — click "+ Add another version of this subject" above the unit tree. This moves your current content into a first named version, then lets you add more. Each version has its own independent units/chapters. Learners pick a version on a card screen before seeing chapters, in view.html.

This uses the same "categories" shape the learner app already understands — no separate setup needed on the learner side.
4. JSON template & import

⬇ Download Template

Gives a filled-in example JSON matching the exact shape the builder expects — useful for writing content offline in your own editor.

⬆ Import JSON

Upload a file shaped like the template — either a full new subject, or just units to append into whatever subject you have open. IDs are regenerated automatically so two people's files never collide.

5. Team & editor requests

📋 Editor Requests

Anyone can request to become an editor from the public become-editor.html form. Approving a request opens the "New Team Member" form pre-filled — just set a password and role.

Map subjects

Click "Map subjects" next to an editor to assign them a subject with can-edit / can-publish flags, or remove an existing mapping.

6. Data, Statistics & Feedback

Data — raw registrations/attempts tables. Statistics — per-subject and per-chapter accuracy bars, click a subject to drill in. Feedback — star ratings + comments learners leave (both per-chapter and on the dashboard), with a per-subject breakdown for admins. All three are scoped to an editor's mapped subjects automatically.

7. What "Save" actually does

Clicking 💾 Save Subject to Database writes straight to the live subject_content row — learners see it immediately in view.html, there's no draft/staging step yet. Every save also writes an audit row to subject_update_logs (who, when, before/after) — there's no UI for that history yet, query the table directly if you need to check or roll back a change.
